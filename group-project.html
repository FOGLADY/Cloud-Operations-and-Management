Group Project

Evaluation of Microsoft Azure Resource Manager Architecture and Enterprise Deployment

This group project evaluated Microsoft Azure Resource Manager (ARM) as an enterprise cloud infrastructure framework. The work was completed as part of the Cloud Operations and Management module by a three-person development team.

The report examined how ARM supports the design, deployment and governance of cloud infrastructure across public, private and hybrid environments. It also explored Infrastructure as Code, cloud service models, Azure governance, hybrid-cloud technologies and real-world enterprise cloud adoption.

Project Overview

The project combined theoretical research, architectural analysis and a real-world case study. The first stage examined Azure Resource Manager and its role as Azure's central management and deployment layer. Particular attention was given to Resource Groups, role-based access control, tagging, dependency management and declarative Infrastructure as Code using ARM templates and Azure Bicep.

The report then compared Infrastructure as a Service (IaaS), Platform as a Service (PaaS) and Software as a Service (SaaS), considering how customer responsibility changes across the different service models. Public, private and hybrid cloud deployment models were also evaluated, including technologies such as Azure Arc, Azure Stack and ExpressRoute.

A basic enterprise Azure infrastructure was then designed around compute, storage, networking, security and governance. Finally, Standard Bank Group was used as a real-world case study to evaluate how cloud infrastructure can support digital transformation, scalability and operational efficiency.

Project Approach

The project followed a research-based approach supported by academic, technical and industry sources. The Azure Resource Manager architecture was analysed from both a technical and enterprise-management perspective.

The group examined how ARM provides a unified management layer through which Azure resources can be deployed, organised and governed. ARM templates and Azure Bicep were considered as Infrastructure as Code approaches that allow environments to be deployed consistently and repeatedly.

The analysis also considered the advantages and limitations of different cloud service and deployment models. Rather than viewing public cloud as the only solution, the report examined how hybrid and multi-cloud approaches can address requirements such as data sovereignty, latency, legacy-system integration and regulatory compliance.

My Contribution

My main contribution to the group project was researching the technical and academic background of the topic. I gathered information on Microsoft Azure Resource Manager, cloud service models, Infrastructure as Code, hybrid-cloud technologies and enterprise deployment approaches.

I also researched relevant academic and industry sources to support the report, including material on Azure architecture, NIST cloud service models and real-world cloud adoption. This research helped the group establish a reliable foundation for the technical analysis and supported the evaluation of Azure Resource Manager in an enterprise context.

A particular focus of my research was understanding how ARM supports governance, automation and repeatable deployment, as well as identifying the advantages and limitations of hybrid and multi-cloud approaches. I also contributed research relating to the Standard Bank case study, which helped connect the technical concepts discussed in the report with a real-world example of enterprise cloud transformation.

This contribution improved my ability to identify credible sources, compare technical information from different perspectives and translate research into material that could support a structured cloud architecture evaluation.

Challenges and Learning

One of the main challenges was understanding how the different layers of Azure fit together. Individual cloud services such as Virtual Machines or Storage are relatively straightforward when considered separately, but enterprise cloud architecture requires these services to be combined with networking, identity, governance and security controls.

The project helped me understand that successful cloud deployment is not simply about provisioning infrastructure. Governance must be considered from the beginning. Resource Groups, RBAC, Azure Policy and tagging provide mechanisms for controlling access, enforcing standards and tracking resources across larger environments.

Another important learning point concerned the trade-off between control and operational responsibility. IaaS provides greater control but requires the customer to manage more of the technology stack, whereas PaaS and SaaS reduce administrative overhead but can create greater dependence on the cloud provider.

Hybrid cloud was also particularly relevant. Azure Arc and ExpressRoute demonstrated how an organisation can integrate existing infrastructure with cloud services rather than treating cloud migration as an all-or-nothing decision.

Real-World Application: Standard Bank Group

The Standard Bank case study helped connect the theoretical architecture with real enterprise cloud adoption. Standard Bank has used Azure alongside other cloud platforms as part of its wider digital transformation strategy.

Its migration of SAP-related workloads demonstrated how cloud technology can support application modernisation, scalability and reduced reliance on traditional on-premises infrastructure.

The case study also demonstrated that cloud adoption does not automatically reduce every type of cost. Capital expenditure on physical infrastructure may fall while cloud subscriptions and software expenditure increase. This reinforced the importance of ongoing cost management and FinOps rather than assuming that cloud services are inherently cheaper.

Project Outcome

The final report concluded that Azure Resource Manager provides a strong framework for enterprise cloud management because it combines Infrastructure as Code, centralised governance and consistent resource management.

The project identified several important principles for successful enterprise cloud adoption. Governance and identity should be established before large-scale deployment, hybrid technologies can help organisations balance cloud innovation with existing infrastructure requirements, and movement towards PaaS and SaaS should be evaluated against control, vendor lock-in and cost considerations.

The Standard Bank case study further demonstrated that cloud adoption should be considered an organisational and operating-model transformation rather than simply a replacement for physical servers.

Reflection

This project developed my understanding of cloud architecture beyond individual services. Before the project, it was easier to think about cloud technologies separately, such as virtual machines, storage or networking. Evaluating Azure Resource Manager helped me understand how these services are organised and governed as part of a complete enterprise architecture.

Working with a group also required technical information from different areas to be combined into a single coherent report. This highlighted the importance of consistency, communication and critical evaluation when producing collaborative technical work.

The most valuable lesson was that cloud architecture involves trade-offs. Greater automation can improve consistency but requires strong governance; managed services reduce operational workload but can increase provider dependency; and hybrid cloud provides flexibility but introduces additional architectural complexity.

These lessons directly supported later topics in the module, particularly hybrid cloud, cloud security, Infrastructure as Code, migration and the individual cloud strategy project.
