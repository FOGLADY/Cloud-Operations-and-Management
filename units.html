Unit 1 – Introduction to Cloud Fundamentals and Services

Overview

Unit 1 introduced the fundamental concepts of cloud computing and established the foundation for the rest of the module. The unit covered the evolution and characteristics of cloud technologies, the three main service models — Infrastructure as a Service (IaaS), Platform as a Service (PaaS) and Software as a Service (SaaS) — and the advantages and challenges associated with cloud adoption.

Key Learning

Through the lecture, reading and seminar activities, I developed a clearer understanding of how responsibility is divided between the customer and cloud provider across IaaS, PaaS and SaaS. I also learned that cloud adoption is not simply a technical decision. Scalability, flexibility and reduced infrastructure management can provide significant benefits, but organisations must also consider security, compliance, cost management and vendor lock-in.

The formative activity required a comparison of AWS and Google Cloud. This helped me understand that although major providers offer many equivalent services, differences in pricing, ecosystems, management tools and specialist capabilities can influence which platform is most appropriate for a particular organisation.

Application and Reflection

This unit provided the conceptual basis required for later topics such as cloud architecture, automation, security and hybrid cloud. One of the most useful aspects was moving beyond simply memorising the definitions of IaaS, PaaS and SaaS and considering how each model would affect a real organisation's level of control and responsibility.

The unit also introduced the e-Portfolio process and GitHub setup. Establishing the portfolio at the beginning of the module provided a structured way to record practical work and reflect on how my cloud knowledge develops throughout the course.

Artefacts / Evidence

  • AWS vs Google Cloud formative discussion
  • GitHub e-Portfolio setup
  • Unit 1 reading and seminar activities

Unit 2 – Understanding Cloud Architecture and Implementing Different Frameworks

Overview

Unit 2 focused on the structure and design of cloud environments and introduced several frameworks that can be used to plan and manage cloud systems. The main topics were cloud architecture, TOGAF, the Software Development Life Cycle (SDLC), and Infrastructure as Code (IaC).

Key Learning

Through the reading and formative activity, I developed a better understanding of how architectural frameworks such as TOGAF can support the planning of complex cloud environments. I also learned how SDLC principles can be applied in cloud-based development, helping to organise the stages of planning, development, testing, deployment and maintenance.

A particularly important concept introduced in this unit was Infrastructure as Code. IaC showed how infrastructure can be defined and deployed through code rather than configured manually. This improves consistency, repeatability and automation, and reduces configuration differences between environments.

The formative discussion on ROCCA and TOGAF helped me consider different approaches to cloud architecture and how frameworks can guide decision-making rather than relying on ad hoc infrastructure design.

Application and Reflection

This unit helped me understand that effective cloud architecture depends not only on choosing the right services, but also on following structured processes and design principles. The introduction to IaC was especially useful because it connects directly to later topics such as Terraform, automated deployment and DevOps.

I also found it useful to compare traditional architectural frameworks such as TOGAF with more cloud-focused approaches. This showed me that established enterprise architecture principles can still be valuable in modern cloud environments, but they often need to be adapted to support automation, scalability and rapid deployment.

Artefacts / Evidence

  • ROCCA and TOGAF formative discussion
  • Unit 2 reading on cloud architecture frameworks
  • Introduction to IaC and automated infrastructure management

Unit 3 – Cloud Design Tools

Overview

Unit 3 focused on the role of Artificial Intelligence in cloud computing and how AI-driven technologies can support automation, optimisation and monitoring within cloud environments. The unit also revisited cloud architecture frameworks and Infrastructure as Code.

Key Learning

Through the lecture, reading and formative activities, I developed a stronger understanding of how AI can improve cloud operations. Machine learning and data analytics can be used to identify usage patterns, optimise resource allocation, detect anomalies and support automated decision-making across cloud environments.

The unit also highlighted how AI can contribute to areas such as cloud security, data management and infrastructure monitoring. Rather than treating AI as a separate technology, I learned to view it as something that can be integrated into existing cloud services to improve performance and operational efficiency.

The formative discussion on cloud design tools encouraged me to research a specific tool and consider how different platforms support the design and management of cloud infrastructure. Reviewing the work of other students provided additional perspectives on different tools and use cases.

Application and Reflection

This unit helped me understand the relationship between cloud architecture, automation and AI. I found it particularly useful to see how AI can support infrastructure management rather than only being used for end-user applications.

The unit also reinforced the importance of selecting cloud tools based on the problem being solved rather than choosing technology simply because it is popular.

  • Cloud Design Tools formative discussion
  • Peer response to another student's discussion post
  • Unit 3 reading on Generative AI in cloud computing
  • Cloud computing fundamentals activity

Unit 4 – Cloud Native Technology Part 1

Overview

Unit 4 focused on the practical tools used to manage and automate cloud environments. The unit introduced scripting languages such as Bash and Python, GUI-based cloud tools, Microsoft Azure and OpenStack.

Key Learning

I developed a better understanding of how scripting can reduce repetitive administrative work and improve consistency in cloud environments. Bash scripting demonstrated how tasks such as configuration, deployment and system management can be automated instead of performed manually.

The unit also introduced GUI-based management tools and highlighted the differences between graphical administration and command-line or script-based approaches. While GUI tools can make cloud management easier to understand and operate, scripting provides greater repeatability and is more suitable for automation.

Application and Reflection

The formative activity required the development and execution of a Bash script together with an explanation of its purpose. This helped me connect scripting knowledge with practical cloud administration.

The unit also strengthened my understanding of Azure and OpenStack as platforms for managing infrastructure and prepared me for later topics involving containers, orchestration and cloud automation.

Artefacts / Evidence

  • Bash scripting formative activity
  • 500-word Bash script explanation
  • Unit 4 reading on GUI tools and OpenStack
  • Cloud architecture and IaC seminar activities

Unit 5 – Cloud Native Technology Part 2

Overview

Unit 5 introduced cloud-native application development, focusing on the 12-Factor App methodology, containers and Kubernetes. The unit examined how cloud-native principles can support scalable, resilient and portable applications.

Key Learning

I learned that cloud-native development involves more than simply hosting an application in the cloud. Principles such as separating configuration from code, treating backing services as attached resources and designing applications for horizontal scaling help make applications easier to deploy and manage.

Kubernetes introduced the concept of container orchestration. I developed an understanding of how Kubernetes can manage containerised applications, including deployment, scaling and recovery, and why orchestration becomes important when applications consist of multiple containers or services.

Application and Reflection

The formative activity involved setting up a Kubernetes cluster using Minikube. This gave me practical experience with the basic process of creating and managing a cluster rather than only learning Kubernetes terminology.

The exercise also helped me understand that Kubernetes introduces additional complexity. It is powerful for larger distributed systems, but it is not automatically the best solution for every cloud workload.

Artefacts / Evidence

  • Minikube Kubernetes cluster deployment
  • Kubernetes deployment discussion
  • Cloud configuration activity
  • Unit 5 cloud-native technology reading

Unit 6 – Hybrid Cloud Solutions: Hybrid, Fog and Edge Computing

Overview

Unit 6 focused on hybrid cloud architectures and the integration of on-premises infrastructure with cloud, fog and edge computing technologies. The unit also considered multi-cloud management and the problem of vendor lock-in.

Key Learning

I developed an understanding of why organisations may choose hybrid cloud instead of moving every workload into the public cloud. Legacy systems, latency requirements, sensitive data and local hardware can all justify retaining part of an infrastructure on-premises.

The unit also clarified the distinction between cloud, fog and edge computing. Edge computing processes data close to where it is generated, while fog computing can provide an intermediate processing layer between edge devices and central cloud services.

Application and Reflection

The formative activity required the design of a hybrid architecture using OpenStack and the simulation of edge devices for a real-time IoT scenario. This helped me understand how different infrastructure layers can work together rather than being treated as separate technologies.

The unit also made me more aware of vendor lock-in. I learned that portability, open standards and careful architecture decisions should be considered early rather than only after an organisation becomes dependent on a specific provider.

Artefacts / Evidence

  • Hybrid cloud architecture design
  • Fog computing integration activity
  • Edge-device IoT simulation
  • Development Team Project and peer review

Unit 7 – Cloud Security and Compliance

Overview

Unit 7 introduced the security and regulatory considerations associated with cloud computing. The unit covered cloud security risks, security assessment, GDPR, ISO/IEC 27001 and techniques for protecting cloud and hybrid environments.

Key Learning

I learned that cloud security is based on both technical and organisational controls. Encryption, access management, network security and monitoring are important, but organisations must also consider governance, compliance and responsibility for data.

The unit reinforced the importance of understanding the shared responsibility model. Moving infrastructure to a cloud provider does not remove the customer's responsibility for secure configuration, access control and appropriate handling of data.

Application and Reflection

The formative activity involved conducting a mock security audit and producing recommendations based on the findings. This helped me think about security from an assessment perspective rather than simply listing individual controls.

I found this useful because it demonstrated how weaknesses such as excessive privileges or poor configuration can create risk even when the underlying cloud platform is secure.

Artefacts / Evidence

  • Mock cloud security audit
  • Security recommendations and findings
  • Hybrid cloud solutions activity
  • Unit 7 security and compliance reading

Unit 8 – Disaster Recovery and Business Continuity

Overview

Unit 8 focused on disaster recovery and business continuity in cloud environments. The unit examined how organisations can maintain or restore important services following outages, cyber incidents or infrastructure failures.

Key Learning

I developed a clearer understanding of the difference between disaster recovery and business continuity. Disaster recovery focuses on restoring systems and data after disruption, while business continuity considers how the organisation continues to provide essential services throughout an incident.

The unit also introduced cloud-based disaster recovery technologies such as Azure Site Recovery and AWS Elastic Disaster Recovery. I learned that an effective recovery strategy must consider backup, replication, geographic redundancy and recovery priorities rather than relying on backups alone.

Application and Reflection

The formative activity required the design of a disaster recovery plan. This helped me understand the importance of identifying critical services, dependencies and recovery procedures before an incident occurs.

One of the most important lessons was that a recovery plan should be tested regularly. A backup or recovery process that has never been tested cannot be assumed to work when a real failure occurs.

Unit 9 – Cloud Migration and Integration Strategies

Overview

Unit 9 examined strategies for migrating legacy systems and data into cloud environments. The unit considered migration planning, integration between cloud and on-premises systems, and tools such as AWS Database Migration Service and Azure migration technologies.

Key Learning

I learned that cloud migration is not simply a process of copying applications or databases from one location to another. Organisations need to consider compatibility, downtime, dependencies, security, performance and rollback procedures.

The unit also introduced the importance of choosing an appropriate migration strategy for each workload. Some systems can be moved with relatively little modification, while others may need to be modernised or redesigned before they can take full advantage of cloud capabilities.

Application and Reflection

The formative task involved migrating a MySQL-compatible database from a local environment to Microsoft Azure using an appropriate migration method. This provided practical experience with the type of data-transfer and compatibility issues that may arise during migration.

The activity helped me appreciate that migration planning should include validation and recovery options rather than focusing only on completing the transfer successfully.

Artefacts / Evidence

  • MySQL database migration activity
  • Cloud migration strategy activity
  • Security risk assessment activity
  • Unit 9 hybrid/multi-cloud migration reading

Unit 10 – Advanced Cloud Technologies: Serverless Computing

Overview

Unit 10 introduced serverless computing and examined services such as AWS Lambda, Azure Functions and OpenFaaS. The unit focused on how serverless architectures allow developers to execute code without directly managing the underlying infrastructure.

Key Learning

I learned that serverless computing can improve scalability and operational efficiency because infrastructure provisioning and scaling are handled by the platform. It can also reduce cost for workloads that run intermittently because resources do not need to remain permanently active.

However, the unit also showed that serverless architectures have limitations. Vendor dependency, execution limits, debugging complexity and cold-start delays may make them unsuitable for some workloads.

Application and Reflection

The formative activity involved implementing a serverless function using OpenFaaS and discussing the deployment process. This gave me practical insight into how functions can be packaged and executed on demand.

I found the comparison between traditional servers, containers and serverless especially useful. It demonstrated that cloud architecture is based on selecting the most appropriate execution model for a workload rather than assuming that newer technology is always better.

Artefacts / Evidence

  • OpenFaaS serverless function
  • OpenFaaS discussion
  • Cloud migration strategy activity
  • Unit 10 serverless computing reading

Unit 11 – AI and Cloud Computing

Overview

Unit 11 explored the relationship between Artificial Intelligence and cloud computing. The unit examined how cloud platforms provide scalable computing resources for machine learning, natural language processing and data analytics, while AI can also improve cloud automation, monitoring and resource management.

Key Learning

I learned how major providers integrate AI services into their cloud ecosystems, including AWS SageMaker, Google AI and Azure AI. The unit also demonstrated how AI can support cloud operations through anomaly detection, forecasting, automation and optimisation.

A major learning point was that cloud computing and AI increasingly depend on each other. AI workloads often require scalable compute and storage resources, while cloud platforms can use AI to make their own services more intelligent and efficient.

Application and Reflection

The formative activity involved using TensorFlow and Keras to build and deploy a simple image-recognition model. This helped me connect AI theory with an actual cloud use case and understand the steps involved in preparing, training and deploying a model.

This unit also directly informed my individual coursework, where AI was incorporated into a broader cloud strategy. It helped me distinguish realistic operational uses of AI from more complex clinical or high-risk applications that require stronger governance.

Artefacts / Evidence

  • TensorFlow and Keras image-recognition activity
  • AI deployment reflection
  • Unit 11 AI and cloud reading
  • Development Individual Project

Unit 12 – Future Trends in Cloud Computing

Overview

Unit 12 concluded the module by examining emerging technologies that may influence the future of cloud computing. The main topics included Artificial Intelligence, blockchain, quantum computing and developments in edge computing and data integrity.

Key Learning

I developed a better understanding of how cloud platforms are likely to evolve beyond traditional compute and storage services. AI is becoming increasingly integrated into cloud operations, while edge computing is allowing more processing to occur closer to users and devices.

Blockchain was considered in relation to distributed trust and data integrity, while quantum computing introduced a longer-term model for solving specialised computational problems. I learned that emerging technologies should be evaluated according to practical value and maturity rather than adopted simply because they are innovative.

Application and Reflection

The formative discussion on AI, blockchain and quantum computing encouraged me to consider which technologies are likely to have near-term operational value and which remain more experimental.

Looking back across the module, my understanding developed from basic cloud service models to architecture, automation, containers, hybrid cloud, security, recovery, migration, serverless computing and AI. I also became more confident in evaluating trade-offs rather than viewing cloud technologies individually.

This final unit reinforced the importance of continuous learning in cloud computing because platforms, tools and best practices evolve rapidly.
